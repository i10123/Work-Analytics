# Спецификация и План разработки: Work analytics (Web App)

## 1. Executive Summary (Краткое резюме)
Веб-приложение для сбора, агрегации и визуализации данных об IT-вакансиях. Система состоит из Node.js/Express бэкенда с встроенным асинхронным краулером и фронтенда на Vanilla JS с чистым CSS. Парсер собирает данные с HH.ru, Rabota.by (через API) и Хабр Карьеры (через парсинг HTML с защитой от блокировок). Данные сохраняются исключительно в JSON-файлы (без СУБД). Реализована поддержка мультивалютности с конвертацией через внешнее API и уведомления реального времени (SSE).

## 2. Problem Statement (Постановка задачи)
Студенту необходимо провести статистический анализ рынка труда для курсовой работы. Использование классических СУБД запрещено. Требуется полноценный веб-интерфейс с настройками параметров парсинга и фоновым выполнением задач. Клиент должен получать данные в реальном времени, а код должен быть написан чисто, задокументирован и легко объясним на защите.

## 3. Success Criteria (Критерии успеха)
1. Пользователь может задать параметры поиска (ключевое слово, период, лимит) через UI.
2. Сервер парсит 3 источника. Для Хабр Карьеры используются задержки (safe limits), чтобы избежать бана по IP.
3. **Мультивалютность:** Зарплаты отображаются в 3-4 оригинальных валютах, но для графиков конвертируются в единую валюту через стороннее API (с механизмом fallback при падении API).
4. Сервер запускает парсинг в фоне и уведомляет фронтенд о готовности через **Server-Sent Events (SSE)**.
5. Собранные данные сохраняются в `/data/reports/` в формате JSON.
6. Дашборд строит интерактивные графики (Chart.js) на основе JSON-отчета.
7. Интерфейс реализован на **чистом CSS** (Flexbox/Grid, CSS-переменные) без фреймворков.
8. Весь код строго задокументирован (JSDoc), каждый шаг логируется.

## 4. User Journey (Пользовательский путь)
1. Открытие веб-приложения `http://localhost:3000`.
2. В левой панели видна история прошлых отчетов (JSON-файлы) и кнопка "Новый сбор данных".
3. Настройка фильтров: Ключевое слово, Период, Лимит вакансий.
4. Клик "Запустить". Форма закрывается, появляется статус "В процессе".
5. Фронтенд устанавливает SSE-соединение с сервером и ждет сигнала.
6. Когда парсер заканчивает работу, сервер отправляет push-уведомление (SSE). Статус мгновенно меняется на "Готово", графики обновляются автоматически.

## 5. Functional Requirements (Функциональные требования)
- **Бэкенд:** Express.js, REST API + SSE endpoint (`/api/events`).
- **Сбор данных:** Axios (для API) + Cheerio (для HTML). Обязательные паузы между запросами к Хабру (1-2 сек).
- **Валюты:** Интеграция с API курсов валют (например, ExchangeRate-API). При недоступности API используются жестко заданные резервные курсы (fallback).
- **Фронтенд:** Vanilla JS, Chart.js (Вилки ЗП, Навыки, Опыт). Чистый CSS.

## 6. Правила к написанию кода (Code Guidelines)
- **Язык комментариев:** Русский. Подробное объяснение каждой функции и сложной логики.
- **Документация:** Строгое использование JSDoc для каждой функции (описание параметров `@param` и возвращаемых значений `@returns`).
- **Логирование:** Использование `console.log` с префиксами (например, `[Parser]`, `[API]`, `[Storage]`) на каждом логическом шаге.
- **Модульность:** Разделение логики по файлам (роуты, сервисы, парсеры).
